# ime-week01-reflection
From Code Errors to Logical Awakening: Why Design Students Still Need to Learn Programming

While preparing my portfolio, I designed a smart wearable project—a smart necklace that interacts with users through changing light effects. To test the feasibility of this concept, I tried using an Arduino test module to control the lighting effects of the necklace. Since I was not proficient in programming, I directly asked ChatGPT to write a piece of code for me.

AI gave me a seemingly complete and syntactically correct piece of code within seconds. I eagerly copied it into my development environment, but it simply would not run. I was very frustrated at that moment. After repeatedly checking the hardware connections and confirming they were fine, I realized the problem was in the code itself. Because I did not understand the underlying programming logic at all, I had no idea where to start fixing it. I had to force myself to look up information, study the code line by line, and finally discovered that AI had made an error in the logic of the lighting loop, causing the program to crash. After my own research and debugging, the code finally worked, and the necklace lit up exactly as I had envisioned.

This experience deeply convinced me that without knowing basic programming logic, I cannot judge whether AI-generated results are reasonable. I become a passive receiver, accepting whatever AI gives me, with no ability to find bugs or adjust functions based on my product requirements. As Ahmed et al. (2025) point out, generative code tools often produce syntactically correct code that fails to match the real design intent. Beginners without programming literacy cannot identify these hidden defects. Therefore, for design students, learning programming is not about becoming engineers, but about gaining the ability to review and critique AI outputs.

Secondly, this project experience made me realize that learning programming helps me build logical thinking habits. While debugging the lighting code for that smart necklace, I was forced to understand how a program executes step by step, how it loops, and how it makes conditional judgments. This way of "decomposing complex problems" was later transferred to my user research and prototyping—I learned to break complex user requirements into small, clear, and executable steps. Even when I am not writing code, this logical decomposition ability greatly improves my design efficiency. Moreover, when collaborating with engineers, basic programming knowledge helps me communicate design constraints and evaluate technical feasibility more accurately, instead of only handing over static visuals. Studies on AI-assisted design education also point out that in the AI era, designers act as reviewers and curators of AI outputs; human critical judgment remains irreplaceable (Ma et al., 2025).

In conclusion, AI changes how we create, but it does not remove the need for us to understand underlying logic. For me, learning programming is a way to better use AI tools and truly realise my product-design ideas. Generative AI lowers the barrier of writing code, but it raises the requirement for designers to verify, critique and direct computational outputs.
